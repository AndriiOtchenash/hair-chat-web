# hair-chat-web — CLAUDE.md

Frontend (SPA) for a hair-care chatbot (cosmetic advice, NOT medical).
Sibling repos: `hair-chat-api` (FastAPI backend, /workspaces/hair-chat-api), `hair-chat-infra`.
Owner background: senior-ish Java/Spring dev, new to React/TS — explain frontend idioms briefly in
PR descriptions when they differ from Spring conventions.

The backend's CLAUDE.md is the source of truth for the API: SSE contract
(POST /conversations/{id}/messages), error format, auth codes, consents. Read it; never change the
backend from this repo.

## Stack (do not change without an ADR in docs/adr/)

- Node 24, pnpm via corepack (`packageManager` in package.json), Vite 8, React 19, TypeScript strict
  (+ noUncheckedIndexedAccess)
- Tailwind CSS v4 + shadcn/ui (Radix, components copied into src/components/ui, `cn` from `cn`)
- react-router (data router, `createBrowserRouter`), TanStack Query for server state
- react-i18next: uk, pl, en, ru (= backend `Locale`); language from localStorage, else the browser
- @auth0/auth0-react: Authorization Code + PKCE, redirect_uri = window.location.origin, tokens in
  memory, refresh tokens (rotation) with silent-auth fallback
- Typed API: openapi-typescript -> src/shared/api/schema.d.ts
- Tests: Vitest + React Testing Library + MSW; lint: ESLint (typescript-eslint strictTypeChecked) + Prettier

## API conventions

- Browser calls go to `/api/*` (VITE_API_BASE_URL); the Vite dev proxy strips `/api` and forwards
  to http://localhost:8000. No CORS in dev; prod serves the SPA and API behind one origin as well.
- Every call goes through `useApiClient()` (Bearer token from Auth0, `{code, message}` -> ApiError).
  Never call `fetch` directly from components. Server state lives in TanStack Query hooks
  (`features/<x>/use<Thing>.ts`).
- 401 or a failed token refresh -> logout (ApiClientProvider). 4xx are not retried.
- Errors are shown via `useErrorMessage()` by `code` (`errors.<code>` in every locale, fallback
  `errors.unknown`); never show the server's `message` to users. Client-side codes:
  `network_error`, `bad_response`.
- Response types come from schema.d.ts via src/shared/api/types.ts. Regenerate after backend changes:
  `pnpm gen:api` (backend must run on :8000); never edit schema.d.ts by hand.
- SSE chat: `api.stream()` (same token/401/consent handling, errors before the stream are
  ApiError) + `readSSE()` from src/shared/api/sse.ts (own parser: events cut across chunks, CRLF,
  `: ping`; EventSource cannot send Authorization) + `parseChatEvent()`. Logic lives in
  features/chat/useSendMessage.ts: `restart` clears the partial answer; `done` -> refetch messages
  and conversations; Stop aborts (the backend saves no partial answer, the user message stays).
  Rejected before the stream (409/422/503/network) -> the text goes back into the input.
- `done.sources`/`truncated` are not in GET messages: kept in memory only (query key
  `answerMeta`), so they show for answers streamed in this session.
- 403 `consent_required` from any call -> ApiClientProvider refetches consents and navigates to
  /consents (global, no per-screen handling).
- Data rights (backend ADR 0006, /settings "Your data"): `api.download()` for GET /me/export
  (Blob + temporary object URL, name from Content-Disposition, else hair-chat-export.json).
  "To read" = the same JSON rendered here (features/me/exportHtml.ts, ExportDocument.tsx) with
  react-dom/server to one self-contained HTML file in the UI language: data only as React text
  or through <Markdown>, never as raw HTML; react-dom/server stays a lazy chunk (vite.config.ts).
  DELETE /me always sends `{confirm: "DELETE"}` (the UI word is localized). After 204 use
  `useEndSession('/login?deleted=1')`: `api.endSession()` blocks every later call (the backend
  recreates a user from a still-valid token), cache cleared, Auth0 logout. That returnTo must be
  in Auth0 Allowed Logout URLs.

## Routes and consents

- `/login` public; `RequireAuth` -> `/consents`, `/settings`; `RequireAuth` + `RequireConsents`
  -> `/chat`, `/chat/:id` (every chat screen goes under RequireConsents). `/` -> `/chat`.
- Chat routes carry `handle: { fullHeight: true }`: AppLayout/Header go max-w-5xl and the page
  fills the viewport; panes scroll inside. Below md the conversation list is a Sheet.
- Self-harm help lines (safety_notice card): src/features/chat/helplines.ts only; verify every
  number before production.
- Consent texts: `src/consents/<version>/{uk,pl,en,ru}.md`, `CONSENT_VERSION` in
  src/consents/index.ts = backend CONSENT_VERSION. Changed meaning -> new folder + version, never
  edit a released folder (src/consents/README.md). Texts are a DRAFT until legal review.
- POST /consents always sends CONSENT_VERSION. If GET /consents `required_version` differs, show
  the "texts are out of date" error; never send the backend's version for texts we do not have.
- An older-version consent (granted: false, version set) -> "terms have been updated" title.
- Revoking (DELETE /consents/{type}) always asks for confirmation and explains that the chat
  becomes unavailable.

## Language

- UI language: explicit choice in this browser (localStorage `hair-chat.lang`, written only by the
  switchers via `useChangeLanguage`) > browser language. Detection is not cached.
- Explicit choice while signed in -> PATCH /me {locale}; failure = toast only, the UI keeps it.
- `LocaleSync` (once per session): new account (no consent of any version) -> profile takes the UI
  language; returning user without an explicit choice -> UI takes `users.locale`.

## Non-negotiable rules

1. No test touches the network: MSW runs with `onUnhandledFrame: 'error'`; Auth0 is faked
   (src/test/auth0Mock.ts, mocked in setup.ts). Never call real Auth0 or the real API in tests.
   Default handlers (src/test/msw/handlers.ts) are recreated before each test; `consentsHandlers`
   is a stateful fake of /consents. With `server.use` the first matching handler wins.
2. Every UI string goes through i18n and exists in all four locales (i18n.test.tsx checks keys).
3. `AiDisclosure` ("you are chatting with an AI assistant", EU AI Act art. 50) is visible on every
   screen that shows the chat. Chat routes live under `RequireConsents`.
4. No secrets in this repo: a SPA has none. Auth0 domain/client id/audience are public and live in
   .env.development. Tokens never go to localStorage.
5. Never log or send to third parties message content or profile data (analytics, error trackers).
6. Tests assert behaviour through the UI / public functions (RTL queries by role/text), not
   component internals.
7. Layout is checked at 360px wide (and 320–430): no horizontal scroll, 16px side gutters from
   `main`/header `px-4`. Page cards are `w-full` + `max-w-*`; flex children with text get `min-w-0`;
   no fixed widths or `100vw`. Overlays (dialogs, menus, toasts) stay inside the viewport too.
   jsdom has no layout: check in a browser (DevTools device mode) or headless Playwright.

## Deploy (docs/deploy.md)

- Staging: Fly app `hair-chat-web-stg` (fra), `fly deploy -a hair-chat-web-stg --ha=false`.
  `Dockerfile` (node 24 build -> nginx-unprivileged :8080), `nginx/*.template` (rendered at start:
  `AUTH0_DOMAIN`, `API_UPSTREAM`), `fly.toml` (`[build.args]` = public VITE_AUTH0_* values, keep
  equal to .env.development).
- nginx proxies `/api/*` to `hair-chat-api-stg.flycast` (private, `/api` stripped, SSE unbuffered).
- CSP lives in `nginx/security-headers.inc.template`. Exceptions: Auth0 in connect-src/frame-src,
  `worker-src blob:` (auth0-spa-js token worker), `style-src 'unsafe-inline'` (sonner/Radix
  `<style>`). A new third-party origin needs a CSP change; scripts stay `'self'`.
- A new deployed origin must be added to Auth0 (Callback, Logout incl. `/login?deleted=1`,
  Web Origins, Allowed Origins).

## Workflow for the agent

- Branching: GitFlow. Branch names: `feature/*`, `fix/*`, `chore/*`, always cut from `develop`.
  - Work branches → PR into `develop`, **squash** merge.
  - Release: PR `develop` → `main`, **merge commit** (never squash), so main keeps develop's history.
- One checklist item per branch/PR (plan doc numbering, e.g. 1.10a).
- Before coding: restate the item, list files to touch, list tests to add. Wait for "go" if the
  change touches auth or the API contract.
- After coding: run `pnpm lint`, `pnpm test`, `pnpm build`; paste results; update this file if a
  convention changed.
- CI (.github/workflows/ci.yml): jobs lint, test, build on push/PR to develop and main.
