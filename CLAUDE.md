# hair-chat-web — CLAUDE.md

Frontend (SPA) for a hair-care chatbot (cosmetic advice, NOT medical).
Sibling repos: `hair-chat-api` (FastAPI backend, /workspaces/hair-chat-api), `hair-chat-infra`.
Owner background: senior-ish Java/Spring dev, new to React/TS — explain frontend idioms briefly in
PR descriptions when they differ from Spring conventions.

The backend's CLAUDE.md is the source of truth for the API: SSE contract
(POST /conversations/{id}/messages), error format, auth codes, consents. Read it; never change the
backend from this repo.

## Stack (do not change without an ADR in docs/adr/)

- Node 24, pnpm via corepack (`packageManager` in package.json), Vite 8, React 19, TypeScript strict
  (+ noUncheckedIndexedAccess)
- Tailwind CSS v4 + shadcn/ui (Radix, components copied into src/components/ui, `cn` from `cn`)
- react-router (data router, `createBrowserRouter`), TanStack Query for server state
- react-i18next: uk, pl, en, ru (= backend `Locale`); language from localStorage, else the browser
- @auth0/auth0-react: Authorization Code + PKCE, redirect_uri = window.location.origin, tokens in
  memory, refresh tokens (rotation) with silent-auth fallback
- Typed API: openapi-typescript -> src/shared/api/schema.d.ts
- Tests: Vitest + React Testing Library + MSW; lint: ESLint (typescript-eslint strictTypeChecked) + Prettier

## Layout

src/app App, AuthProvider, routes, queryClient (composition root)
src/components shared app components (AiDisclosure, layout/Header, LanguageSwitcher)
src/components/ui shadcn/ui, generated by `pnpm dlx shadcn add <name>`; edit sparingly
src/features/<x> pages + hooks of one feature (auth, me; later chat, consents)
src/shared/api fetch wrapper (client.ts), ApiError, ApiClientProvider/useApiClient,
useErrorMessage, schema.d.ts (generated), types.ts (aliases from schema)
src/shared/config typed access to import.meta.env
src/i18n i18next init + locales/*.json (en.json is the reference for typed keys)
src/test setup.ts, MSW server/handlers, Auth0 fake, renderApp helper

## API conventions

- Browser calls go to `/api/*` (VITE_API_BASE_URL); the Vite dev proxy strips `/api` and forwards
  to http://localhost:8000. No CORS in dev; prod serves the SPA and API behind one origin as well.
- Every call goes through `useApiClient()` (Bearer token from Auth0, `{code, message}` -> ApiError).
  Never call `fetch` directly from components. Server state lives in TanStack Query hooks
  (`features/<x>/use<Thing>.ts`).
- 401 or a failed token refresh -> logout (ApiClientProvider). 4xx are not retried.
- Errors are shown via `useErrorMessage()` by `code` (`errors.<code>` in every locale, fallback
  `errors.unknown`); never show the server's `message` to users. Client-side codes:
  `network_error`, `bad_response`.
- Response types come from schema.d.ts via src/shared/api/types.ts. Regenerate after backend changes:
  `pnpm gen:api` (backend must run on :8000); never edit schema.d.ts by hand.
- SSE chat (later): use fetch + a stream reader (EventSource cannot send Authorization); handle
  `safety_notice`, `token`, `restart` (clear partial answer), `done`, `error`, `: ping`.
- Chat screens need consents first: on 403 `consent_required` route the user to the consent screen.

## Non-negotiable rules

1. No test touches the network: MSW runs with `onUnhandledFrame: 'error'`; Auth0 is faked
   (src/test/auth0Mock.ts, mocked in setup.ts). Never call real Auth0 or the real API in tests.
2. Every UI string goes through i18n and exists in all four locales (i18n.test.tsx checks keys).
3. `AiDisclosure` ("you are chatting with an AI assistant", EU AI Act art. 50) is visible on every
   screen that shows the chat.
4. No secrets in this repo: a SPA has none. Auth0 domain/client id/audience are public and live in
   .env.development. Tokens never go to localStorage.
5. Never log or send to third parties message content or profile data (analytics, error trackers).
6. Tests assert behaviour through the UI / public functions (RTL queries by role/text), not
   component internals.

## Commands

corepack enable && pnpm install
pnpm dev # http://localhost:5173, /api -> :8000
pnpm lint # eslint + prettier --check + tsc -b
pnpm format # prettier --write
pnpm test # vitest run (pnpm test:watch for watch mode)
pnpm build # tsc -b && vite build
pnpm gen:api # regenerate src/shared/api/schema.d.ts from a running backend
pnpm dlx shadcn@latest add <component>

## Workflow for the agent

- Branching: GitFlow. Branch names: `feature/*`, `fix/*`, `chore/*`, always cut from `develop`.
  - Work branches → PR into `develop`, **squash** merge.
  - Release: PR `develop` → `main`, **merge commit** (never squash), so main keeps develop's history.
- One checklist item per branch/PR (plan doc numbering, e.g. 1.10a).
- Before coding: restate the item, list files to touch, list tests to add. Wait for "go" if the
  change touches auth or the API contract.
- After coding: run `pnpm lint`, `pnpm test`, `pnpm build`; paste results; update this file if a
  convention changed.
- CI (.github/workflows/ci.yml): jobs lint, test, build on push/PR to develop and main.
